# KazUTB platform localization audit

Audit date: 2026-08-03 UTC. Scope: `app`, `resources/views`, `resources/js`, `routes`, `lang`, seeders, middleware, mail/notifications, validation, errors, print/CSV surfaces, the role crawler, and browser tests.

## Baseline

Before this stage, the application defaulted and fell back to Russian. Locale state was split between query parameters and session state; the authenticated user preference was not consistently authoritative; the language cookie and a safe same-page POST switch were absent. Member and librarian layouts contained English shell labels, while the old product label appeared throughout public, member, staff, admin, auth, title, notification-content, and seed surfaces.

The focused source inventory found 157 occurrences of the prohibited old product label and 12 occurrences of the reported English shell phrases (`My Library`, its subtitle, catalogue CTA, sign-out, operations and console labels). The initial translation tree contained 2,844 scalar keys per locale. A semantic review found 90 non-translated EN/KK values in the data-quality and incident dictionaries (59 + 31). These were translated without changing database enum values or user/bibliographic content.

## Classification results

1. Hardcoded English: the reported shell phrases were removed from rendered RU/KK surfaces; current occurrences are EN translations, audit signatures, tests, or an intentionally preserved legacy-notification value.
2. Hardcoded Russian/Kazakh: system labels used by the protected layouts were moved to the locale dictionaries. Curated public articles/events and bibliographic/user content remain data and are not machine-translated.
3. Missing keys: none in the final parity run.
4. Structure differences: none.
5. Empty or raw-key values: none.
6. Suspicious identical values: none outside the explicit international-term allowlist.
7. Placeholder mismatches: none.
8. Plural/date/number handling: translated plural labels remain in Laravel dictionaries; notification dates now use `LocalizedText` and locale-specific long formats. Operational machine-oriented tables may retain an unambiguous numeric date format.
9. JavaScript: role/browser paths were checked for raw keys, mixed shell labels, console exceptions and failed 500 requests.
10. Validation, notification/email, error, branding and accessibility strings: covered by the parity audit and localization feature tests.

## Explicit allowlist

`API`, `CSV`, `DOI`, `Excel`, `ISBN`, `ISSN`, `KazUTB`, `MARC`, `ORCID`, `PDF`, `QR`, `URL`, `English`, `UTC`, `ID`, `RDR00000001`.

UDC is displayed as `ӘОЖ` in KK, `УДК` in RU and `UDC` in EN where the surface supplies a localized label. Bibliographic titles, names, user messages, collection names and uploaded documents are excluded from mixed-language detection by design.

## Data and schema notes

- Canonical database codes and enum values were not translated.
- Existing user preferences were not bulk-overwritten by the migration.
- The live demo identities were exercised by the crawler and returned to `kk`; login timestamps and audit records were generated by those checks.
- Bibliographic records do not have a complete three-language field set. Their original values remain visible and require separate library-led metadata enrichment; no translation API or automatic content translation was introduced.
- Existing notifications that contain ready text are displayed unchanged. Only newly generated notifications carry locale-neutral translation metadata.
